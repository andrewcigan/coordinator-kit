# Правила набора — для ревью

Машинные правила проверяет `tests/test-rules.sh`: только то, что есть на любом Mac и в Git Bash (без Python, Node, Ruby); навсегда ничего не удаляется; `.ps1` — только ASCII; без `\r` и BOM; ничего личного; одна версия архива в README и INSTALL. Он входит в `bash tests/run.sh`, который идёт перед каждым коммитом (`.githooks/pre-commit`) и в GitHub Actions на чистых Mac и Windows. Ниже — то, что машина не проверит.

## Инструкции для Claude

Файлы: `INSTALL.md`, `template/CLAUDE.md`, `template/.claude/skills/novoe/SKILL.md`.

- Каждый вызов инструмента приложения — точным именем и со всеми полями, которые он требует. Например, у `start_session`: `initiation`, `context`, `use_worktree`, `cwd`, `title`, `prompt`, `background` не короче 80 знаков.
- У каждого отказа — свой следующий шаг: инструмента нет, сообщение с телефона, первый ход сессии, группы не читаются, человек не нажал «Разрешить».
- Человеку — одно сообщение-отчёт по образцу.
- Факт о приложении Claude — проверенный (дата и как проверили) или с пометкой «не проверено».
- Ревью изменённой инструкции включает **пробный проход**. Помощник выполняет её как участник: шаги с командами — по-настоящему, на поддельной домашней папке; шаги с инструментами приложения — выписывает вызовы с полями. Затем перечисляет, где пришлось угадывать. Каждое такое место — правка.

## Тексты для людей

Файлы: `README.md` и отчёты внутри `INSTALL.md`.

- По-русски, простыми словами, без названий инструментов и команд.
- Человеку даются только шаги, которые Claude сам сделать не может: нажать «Разрешить», перезапустить приложение, открыть сессию с телефона.

## Хуки и установщик

- Хук пропускает сообщение при любом непонятном вводе (выход 0). Блокирует только сторож — и только при точном совпадении с запретом.
- Повторная установка ничего не задваивает и не перезаписывает чужое. Каждая такая ветка — тест в `tests/test-install.sh`.
- Поведение на Windows — тест с путями `C:\…`; он выполняется в GitHub Actions.
